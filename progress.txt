Feature completed: Containerize the application with Docker and Docker Compose

Created all Docker artifacts — no prior implementation existed:

- api/Dockerfile: two-stage build (node:lts builder → node:lts-slim runtime); runtime stage installs
  tesseract-ocr + tesseract-ocr-eng via apt, copies dist/ and production node_modules, also copies
  migrations/ so `docker compose run api npm run migrate` works inside the container; CMD is
  `node dist/index.js`

- client/Dockerfile: two-stage build (node:lts builder runs `vite build` → nginx:alpine runtime);
  copies built dist/ to /usr/share/nginx/html and installs nginx.conf

- client/nginx.conf: serves SPA with `try_files $uri $uri/ /index.html`; proxies /api and /uploads
  to the api service so the nginx container reaches the API in production

- docker-compose.yml (root): three services — postgres:16-alpine with pgdata named volume and
  pg_isready healthcheck; api with depends_on postgres (service_healthy), uploads named volume, env
  from .env; client with port 80 exposed, depends_on api

- docker-compose.override.yml (root): dev overrides — api mounts ./api/src and runs nodemon; client
  mounts ./client/src and runs `vite --host` on port 5173; both skip the production build stage

- api/.dockerignore and client/.dockerignore: exclude node_modules, dist, .env, test files

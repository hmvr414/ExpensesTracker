Feature completed: Locale-aware amount separator parsing during OCR extraction (integration)

Chose this over the remaining description-extraction item because a misparsed separator corrupts the
core money field by 1000x ('40,313' read as 40.313) — a data-integrity bug — while bad descriptions
are only a quality issue. Also fully self-contained: no migration, no web calls.

What was implemented:
- api/src/helpers/parseAmount.ts (new): parseAmount(rawText, localeHint?) deterministic normalizer.
  Strips currency symbols/codes (everything not [0-9.,]); both separators present → last one is the
  decimal sep; same separator repeated → thousands groups; SINGLE separator + exactly 3 trailing
  digits → thousands ('40,313' → 40313) REGARDLESS of locale hint (with one separator there is no
  other decimal evidence, so the PRD's "or" branch always applies — the localeHint param is accepted
  but currently unused, kept for API compat); exception: integer part '' or '0' stays decimal
  ('0.125'); 1–2 (or 4+) trailing digits → decimal. Returns null when no digits survive stripping.
- api/src/routes/import.ts extract route: prompt now requires per-movement rawAmountText (verbatim
  receipt string) + normalized amount, plus a top-level "language" field ('es'/'en') and explicit
  Spanish/COP separator guidance. Server-side, parseAmount(rawAmountText, language) is compared to
  the model amount with a 0.005 epsilon: agree → amountSuspect false; disagree → the DETERMINISTIC
  value wins and amountSuspect true. Missing/unparseable rawAmountText → model amount, suspect
  false. Response now carries top-level `language` (null when model omits it) and per-movement
  rawAmountText + amountSuspect. Nothing persisted at extract time (unchanged); confirm is untouched
  (the UI sends the corrected number).
- Client (Import.tsx): ⚠ icon (data-testid="amount-suspect-warning") beside the Amount input when
  amountSuspect, tooltip via title='Receipt shows "X" — please verify' from rawAmountText; editing
  the amount clears the flag (onAmountChange now also sets amountSuspect false); suspect rows do NOT
  block the Import button. Types: ExtractedMovement.rawAmountText?/amountSuspect? and
  ExtractResponse.language? added as OPTIONAL fields (deliberate deviation from the
  suggestedNewCategory required-field convention, so existing fixtures and manually-added rows don't
  need the fields).

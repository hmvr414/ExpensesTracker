## Iteration 4 — KAN-14: Full movement list for period and filtering by category

### Starting state
All 11 iteration-3 features are complete (see prd_iteration_3.json / progress_iteration_3.txt). Last
recorded test totals: 318 API tests (Jest) + 248 client tests (Vitest), both TypeScript builds clean.

### Goal
A dedicated `/movements` page showing the full table of movements for a selected period — day, week,
month, or a custom date range — with a multi-category filter and a spend-over-time chart header that
respects the active filter, so the user can see at a glance whether spend for a given category went up
or down over time.

### What already exists (reuse, don't rebuild)
- `GET /api/movements` (api/src/routes/movements.ts): already filters by `from`/`to`, single
  `category_id`, `store`, `search`, `payment_method_id`, with `page`/`limit` (max 100) and returns
  `{ data, total, page, limit }`; ordering `date DESC, time DESC NULLS LAST, created_at DESC`.
- `GET /api/dashboard` (api/src/routes/dashboard.ts): period+anchor model with `computeRange` and a
  zero-filled `generate_series` time-series pattern — the reference for bucketing and the helper to
  factor out (keep dashboard output unchanged).
- Client: `PeriodSelector` (components/PeriodSelector.tsx) exports `getPeriodLabel`, `navigatePeriod`,
  `isNextDisabled` — reuse for Day/Week/Month. `MovementForm` for row editing. `Nav` for the new link.
  `api/movements.ts`, `api/dashboard.ts`, `api/categories.ts` for typed wrappers.

### Plan (prd.json) — 4 features, all passes:false
1. functional — Multi-category (`category_id` repeated + CSV) and `uncategorized` filtering on the list
   API, plus a `totalAmount` aggregate and a 200 page-size ceiling. Single `category_id` stays
   backward-compatible (Dashboard + existing tests green).
2. functional — `GET /api/movements/series`: filter-aware, zero-filled spend time series over an
   explicit from/to range with adaptive granularity (hour/day/week/month) and a previous-period delta;
   shared granularity helper in api/src/helpers/timeSeries.ts, dashboard untouched.
3. ui — `/movements` route + nav link + period control (Day/Week/Month via PeriodSelector helpers and a
   Custom date-range mode), URL-synced; the full movements table with header totals, row-edit handoff,
   skeletons, empty state, and pagination.
4. ui — Category multi-select filter (chips + Uncategorized + reset) and a Spend-over-time chart header
   driven by /api/movements/series, with a ▲/▼ trend pill vs the previous period; table, header total,
   and chart stay in sync and refetch together.

### Suggested build order
1 → 2 (backend first, both independently testable) → 3 (page shell + table on feature 1) → 4 (filter +
chart on feature 2). Feature 4 depends on 2 and 3; feature 3 depends on 1.

### Remaining items in prd.json with passes: false

## Iteration 4 — progress log

### [DONE] Feature 1: Multi-category & flexible-range filtering on the movements list API (passes: true)
`GET /api/movements` (api/src/routes/movements.ts) now supports the full filter set the
`/movements` page needs:
- New `parseCategoryIds(raw)` helper parses `category_id` in three forms — single (`category_id=3`),
  repeated (`category_id=3&category_id=7`), and CSV (`category_id=3,7`) — into a deduplicated list of
  positive ints; non-numeric / non-positive tokens are silently dropped (no 400). One-or-more ids → SQL
  `m.category_id = ANY($n)`. Single `category_id` is unchanged, so the Dashboard recent-movements call
  and old tests stay green.
- New `uncategorized=true` param: alone → `m.category_id IS NULL`; combined with ids → widened to
  `(m.category_id = ANY($n) OR m.category_id IS NULL)`. AND-combined with the existing
  from/to/store/search/payment_method_id params.
- Response now includes `totalAmount` (a number) = `COALESCE(SUM(m.amount),0)::float8` over the entire
  WHERE-filtered set, computed in the same query that produces `total` (so it's independent of
  limit/page). Shape is now `{ data, total, totalAmount, page, limit }`.
- `limit` ceiling raised from 100 → 200 (still defaults to 20, still clamps).
- Tests: 11 new cases in api/src/__tests__/movements.test.ts (the
  "multi-category & flexible filtering" describe block). Full API suite: 361 passing, `tsc --noEmit`
  clean.

### IMPORTANT — how to run the API tests in this environment
There are **no local node_modules** and the host is RAM-constrained, so you must run tests inside Docker,
and there are two gotchas:
1. The long-running `expensestracker-api-1` container bind-mounts the **main checkout**
   (`/home/hermannvallejo/projects/ExpensesTracker`), NOT this worktree. Don't `docker exec` into it for
   tests — it won't see your edits. Instead run a throwaway container that mounts THIS worktree's
   `api/src`.
2. ts-jest type-checking OOMs at ~2 GB on this box. Run with `isolatedModules: true` (transpile-only)
   for tests and do a separate `tsc --noEmit` for type safety.

Recipe (writes a temp jest config under api/, runs, then `rm` it):
```sh
cd <this worktree>
cat > api/jest.fast.js <<'EOF'
module.exports = {
  testEnvironment: 'node', maxWorkers: 1, workerIdleMemoryLimit: '512MB',
  roots: ['<rootDir>/src'],
  testMatch: ['**/__tests__/**/*.test.ts', '**/*.test.ts'],
  moduleFileExtensions: ['ts', 'js', 'json'],
  transform: { '^.+\\.ts$': ['ts-jest', { isolatedModules: true }] },
};
EOF
docker run --rm --network expensestracker_default \
  -v "$PWD/api/src:/app/src" -v "$PWD/api/migrations:/app/migrations" \
  -v "$PWD/api/jest.fast.js:/app/jest.fast.js" \
  -e TEST_DATABASE_URL='postgresql://postgres:postgres@postgres:5432/expenses_test' \
  -e NODE_OPTIONS='--max-old-space-size=1536' \
  -w /app expensestracker-api \
  sh -c 'npx jest --config jest.fast.js --runInBand'
# type-check: same image, -w /app, sh -c 'npx tsc --noEmit'
rm api/jest.fast.js
```
Note: the shared `expenses_test` DB makes the full suite occasionally show 1 cross-suite flake (e.g.
new-category.test); re-run or run the suite in isolation to confirm — it's not your change.

### [DONE] Feature 2: Filter-aware spend-over-time series endpoint (passes: true)
New `GET /api/movements/series` (api/src/routes/movements.ts) — declared BEFORE `/:id` so the literal
path wins over the param route.
- Requires `from` & `to` ISO dates. 400s when either is missing, malformed (regex + `new Date` NaN
  check, so `2024-13-40` is rejected), or `from > to`.
- Accepts the SAME filter params as the list endpoint. To guarantee the chart matches the table, the
  shared filter SQL was factored into `buildMovementFilters(query, params)` (category multi/CSV via the
  existing `parseCategoryIds`, `uncategorized`, `payment_method_id`, `store`, `search`). The list `/`
  endpoint was refactored to call this helper too (behavior identical; its 13 tests stay green).
- Adaptive granularity via the new `api/src/helpers/timeSeries.ts` (`chooseGranularity` +
  `timeSeriesFormat`): span ≤1d → hour (`HH24:MI`), ≤92d → day (`YYYY-MM-DD`), ≤730d → week (ISO week,
  Monday label `YYYY-MM-DD`), else month (`Mon YYYY`). Returned as `granularity` in the response.
- Zero-filled buckets via `generate_series` LEFT JOIN-ed onto movements (dashboard pattern). Hourly
  buckets resolve to date+time (`m.date + COALESCE(m.time,'00:00')`); coarser buckets use date only.
  Each point is `{ label, total }` (number), ordered chronologically.
- Previous-period block: equal-length window immediately preceding [from,to] (`windowDays =
  inclusive day count`; prevFrom = from − windowDays, prevTo = from − 1), same filters applied. Response
  shape: `{ granularity, data, comparison: { previousTotal, currentTotal, deltaPct } }`. `deltaPct` is
  null when previousTotal is 0; `currentTotal` is summed from the series points so it always matches.
- `/api/dashboard` is byte-for-byte unchanged (it keeps its own period-anchored bucketing; timeSeries.ts
  is intentionally NOT wired into it — noted in the helper's header comment).
- Tests: 10 new cases in the `GET /api/movements/series` describe block (missing/malformed/inverted
  range 400s, daily zero-fill, granularity boundaries 1/92/730d, category + payment-method filters,
  positive delta, null-on-zero). Full API suite: 370 passing, `tsc --noEmit` clean.
  (Run tests with the Docker recipe documented above under Feature 1.)

The page (Movements.tsx):
- Period control: Day / Week / Month chips + a 'Custom range' chip, built inline reusing PeriodSelector's

- Range math: `periodRange(period, anchor)` mirrors the dashboard (weeks start Monday, month = 1st..last).
  Custom mode sends the inputs directly.
- URL state via `useSearchParams`: period+anchor (default = current month) OR from+to for custom, plus

  opens the shared `MovementForm`; on save it bumps a refreshKey to refetch. Loading skeletons, a
  'No movements in this period' empty state, and a 'Load more' pager.
- Pagination approach: one request per view with `limit = min(page * 50, 200)`; 'Load more' bumps the URL
  `page`, growing the limit and replacing the list with the superset (visually appends, URL round-trips,
  honors the 200 ceiling). `hasMore = loaded < total`.

### [DONE] Feature 4: Category multi-select filter + spend-over-time chart header (passes: true)
All four iteration-4 features are now complete. Feature 4 is UI-only (the API was finished in Features
1 & 2), all in client/src/pages/Movements.tsx + its test file.

Category multi-select control (above the chart):
- A 'Categories' dropdown button (`aria-haspopup="listbox"`, count badge) opens a `role="listbox"`
  popover of every category (colored swatch + name from `getCategories`, loaded once on mount) each as a
  `role="option"` toggle, plus an 'Uncategorized' pseudo-option at the bottom.
- Selected categories render as removable colored chips (× button, `aria-label="Remove <name>"`) with an

- Selection is mirrored into the URL via the existing param model. New `setSelection(ids, uncat)` rebuilds
  the URL from the active view (period+anchor OR custom from/to), resets page to 1, appends repeated
  `category_id` and sets `uncategorized=true`. `toggleCategory`, `toggleUncategorized`, `resetCategories`
  drive it. (The page already READ category_id/uncategorized from the URL since Feature 3 — this adds the
  control that WRITES them.)

Spend-over-time chart header (recharts, Dashboard card styling):
- New `useEffect` fetches `getMovementsSeries({from,to,category_id?,uncategorized?})` on the SAME deps as
  the list (range + categoryKey + uncategorized + refreshKey), so chart and table always refetch together
  and show the exact same rows. Lightweight per-fetch spinner on the chart; full-card `<Skeleton>` only
  before the first series load.
- BarChart fill = the single selected category's color when exactly one real category (and nothing else)
  is selected, else the primary `#6366f1`. X-axis ticks formatted by the new exported `formatSeriesTick`
  helper keyed off the response `granularity` (day/week ISO → MM/DD; hour HH:MI and month 'Mon YYYY' pass
  through). Tooltip shows the bucket label + `$`-formatted total.
- Header shows `comparison.currentTotal` ($) and a `data-testid="trend-pill"`: ▲ green (success) when
  deltaPct ≥ 0, ▼ red (danger) when < 0, `|deltaPct|.toFixed(1)%` + 'vs previous {period}' caption. Pill
  is hidden when `previousTotal === 0` or `deltaPct == null`. Friendly 'No spend to chart for this
  selection' empty state when every series point is 0.

Tests: 13 new cases added to client/src/__tests__/Movements.test.tsx (now 24 in that file) — series fetch
